## GDELT live probe (2026-09-04, keyless, default egress IP)

1. `GET /api/v2/doc/doc?query=Mullaperiyar sourcecountry:IN&mode=artlist&format=json&maxrecords=5&sort=hybridrel`
   → `HTTP 429`, body (verbatim, truncated to the operative sentence):
   `Please limit requests to one every 5 seconds or contact kalev.leetaru5@gmail.com for larger queries.`
   This CONFIRMS: endpoint live, keyless, documented throttle "one request every 5 seconds".
2. Immediate retry with `sourcelang:eng` + `timespan=14d` after ~7s
   → `ConnectTimeoutError` (egress-side soft throttle after the 429).
   This CONFIRMS the provider must self-throttle (implemented: 6s + 1 retry
   with backoff) and must treat sustained throttling as a provider note with
   fallback to committed fixtures — never as a hard failure of the pass.

## GDELT capability answers (measured / documented)

| Question | Answer |
|---|---|
| availability | Live, keyless. Soft rate-limit on burst / shared IPs (observed 429 + timeout). |
| response format | JSON `artlist`: `{ url, url_mobile, title, seendate (YYYYMMDDTHHMMSSZ), domain, language, sourcecountry }`. |
| rate limits | Documented "one request every 5 seconds"; provider implements 6s self-throttle + 1 retry. |
| India coverage | `sourcecountry:IN` restricts to India-published outlets (query-side, observed in docs + provider). |
| Tamil coverage | `sourcelang:tam` / `sourcelang:eng` splits the language query without dropping the other (provider implements; Tamil recall measured in the discovery experiment, not asserted here). |
| URL quality | Original publisher URLs (`url`, sometimes `url_mobile`); canonicalised by `normalize.ts` (tracking params / AMP / mobile stripped, no fetch). |
| publisher metadata | `domain` per article; resolved via `publisher-resolve.ts` (registry → curated domain map → domain-family fallback). |
| latency | Seconds per call when not throttled; the pass budgets 5 queries × 6s throttle per cluster and caps at 5 calls/event, so online GDELT runs belong in the scheduled production workflow only. |
| original publishers? | Yes — results point at the publisher's own page; IFFA links out, never republishes. |
| body retrieval required? | No. DISCOVERY_ONLY: title + domain + timestamp + language is sufficient for the same-event gate; bodies are never fetched. |

## Architecture (no paid credentials on the default path)

- `DiscoveryProvider` abstraction (`types.ts`): `id · kind · network · enabled · discover(event, queries, ctx)`.
- `loadProviders()` allow-lists via `DISCOVERY_PROVIDERS`; unset → only no-network `corpus-rescan` runs, so `npm test`, `npm run build`, CI never touch the network.
- Deploy workflow sets `DISCOVERY_PROVIDERS=gdelt,corpus-rescan` (online, throttled); `DISCOVERY_OFFLINE=1` replays committed `src/data/fixtures/discovery/gdelt/*.json` fixtures with zero network.
- Future Tavily / Brave / SerpAPI providers implement the same interface; they stay `enabled: false` unless their key env var is present, and are never required for CI or the default demo.
